CLAUDE-Call real_team_task() right after tud_task()

The restructure moved the module hook to the end of the main loop. A config
loaded from the drive (vdisk_task) was then only put into effect
(config_updated -> set_mapping_from_config) on the next pass, after
process_mapping() had already run with the new config and the old mapping
tables. After a config load the device dropped off USB ("Device Descriptor
Request Failed") and the new config was not saved. The hook is back where
vdisk_task() used to be, so the config takes effect in the same pass, as
upstream does for configs from the web tool.
